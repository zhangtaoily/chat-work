# 技能市场部门可见性隔离（通用 + 本部门专属，防越权）

## Context

用户需求：技能分「通用」「专属」两类，防止越权——用户**只能安装自己所在部门的技能 + 通用技能**，其他非通用（他科室专属）技能**不可见**。

现状排查结论（两个缺口 + 一处已覆盖）：

| 环节 | 现状 | 结论 |
|---|---|---|
| 安装越权 | [main.py](file:///d:/prj/chat-work/services/agent_core/agent_core/api/main.py) L769-774 已按 `auth.dept.split("/")[-1] != dept_scope` 尾段匹配 403 | ✅ 已有（口径对齐 permissions.check_dept_scope，graph.py L963 运行时再校验一次，纵深防御成立） |
| 广场可见性 | `GET /skills`（L691-707）仅过滤 status/category/关键词，**无部门过滤**，他科室专属技能全员可见 | ❌ 本次补 |
| 详情直访 | `GET /skills/{name}`（L740-751）不过滤，列表藏了也能直接 URL 看 | ❌ 本次补 |
| personal 类 | 无任何可见性约束，他人可安装 | ❌ 顺带补（最小惊讶原则） |

可复用资产：`category` 三分类 official/dept/personal 与 `dept_scope` 字段已存在（[store.py](file:///d:/prj/chat-work/services/agent_core/agent_core/skills/store.py) L41-42、L77-78）；`dept_scope` 存科室名（「生产科」「销售科」…，registry.py L240-423）；测试先例 test_skill_store.py L229-240。

## 可见性口径（单一规则）

- `official`（通用）→ 全员可见
- `dept`（专属）→ `dept_scope == auth.dept 尾段`，与 install/permission 既有口径完全一致
- `personal` → 仅本人可见（`submitted_by == user_id`）
- **评审视角豁免**：`include_unpublished=true`（dept_manager/security_reviewer 门禁已存在）保持**全量不过滤**——评审员必须能看到他科室提交的 in_review 技能才能评审，此豁免是评审工作台数据源，不改

## 改动清单

### 1. skills/store.py — 新增可见性纯函数

```python
def is_visible_to(meta: dict[str, Any], *, user_id: str, dept: str) -> bool:
    """市场可见性（部门隔离）：official 全员 / dept 本科室（尾段匹配，对齐
    permissions.check_dept_scope）/ personal 仅本人。评审视角豁免在 API 层按
    角色与 include_unpublished 门禁处理，与本函数正交。"""
```

同步无 IO，与既有 `status()` 等查询函数同区放置。上架状态门禁（published）仍由 `list_meta` 现有逻辑负责，两过滤叠加不冲突。

### 2. api/main.py — 三个端点

- `skills_marketplace`（L691）：`include_unpublished=true` 管理员评审视角维持现状全量；普通视角追加 `items = [m for m in items if store.is_visible_to(m, user_id=auth.user_id, dept=auth.dept)]`
- `skill_detail`（L740）：`meta is None or not store.is_visible_to(...)` → 404（用 404 而非 403，避免向未授权者泄露技能存在性）
- `install_skill`（L754）：保留既有 dept 尾段 403；补一条 personal 越权拦截——`category == "personal" and meta["submitted_by"] != auth.user_id` → 403「个人技能仅本人可用」
- 卸载端点不动（只能卸自己的授权，无部门语义）

### 3. 桌面端 MarketView — 零改动

列表来自 `GET /skills`，后端过滤后他科室技能自然消失；现有「科室技能」筛选与 dept_scope 紫色 Tag 展示保留。不需碰 App.tsx/api.ts。
